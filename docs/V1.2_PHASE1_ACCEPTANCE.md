核心执行链路已变为：

```text
API / Market Worker
  -> 读取数据库 Automation / Pause / Kill / Recovery 闸门
  -> 生成 TradePlan
  -> execution.order Outbox（唯一 dedup_key）

       -> 再次读取数据库闸门
       -> RiskEngine
       -> client_order_id 幂等提交
       -> Outbox ack
```

## 1. API、Market Worker、Execution Worker、Recovery Watchdog 跨进程状态共享

### 实现

- 新增 `recovery_checkpoints`：恢复状态、阻断原因、步骤、计数、revision 全部落库。
- 新增 `worker_heartbeats`：role、worker_id、host、pid、状态、运行次数、错误与最近心跳落库。
- Recovery 开始时先写 `RECOVERY_MODE`，结束时写最终检查点；中途崩溃不会让其他进程沿用本地内存。
- API 的 Automation/Recovery/Worker 状态均从数据库读取，不再把 API 进程内存当作事实源。
- Market Worker 在交易关闭时仍刷新行情，但不生成订单任务。

## 2. PostgreSQL 持久化 Automation Control

### 实现

- 单例行 `automation_controls.id='global'` 持久化 `running / paused / environment / revision / updated_by / pause_reason / manual_block_reason`。

## 3. PostgreSQL Outbox

### 实现

- 采用 PostgreSQL Outbox，不依赖 Redis Streams。
- `outbox_messages` 包含 topic、payload、唯一 dedup_key、状态、attempts、owner 和 lease。
- `enqueue` 与调用方事务一致且不自行 commit。
- PostgreSQL 使用 `FOR UPDATE SKIP LOCKED` 原子认领。
- `ack/nack` 校验 owner 与有效租约；支持重试、DEAD、过期租约回收。

## 4. Execution Worker 真正消费订单任务

### 实现

- `run-cycle` 不再直接调用交易所下单，而是写入 `execution.order`。

- `REJECTED` 与 `UNKNOWN` 作为已处理结果 ack；UNKNOWN 不盲目重试。

## 5. `AUTO_TRADING_ENABLED=false` 时任何 Worker 不得创建新订单

### 实现

- `new_order_gate(db)` 是生产者与 Execution Worker 共用的持久化闸门。
- AUTO=false 时 Automation start 返回 403。
- Execution Worker 在 claim 前检查；即使已有 PENDING 任务也不会认领或创建订单。
- Market Worker 仅刷新行情。

## 6. Pause 与 Kill Switch 跨进程生效

### 实现

- Pause 读取 `automation_controls`，Kill Switch 读取 `kill_switch_states`，不依赖 WebSocket 或进程内事件总线。
- 每次 Worker 循环和每次实际提交前都重新读取数据库。
- 普通 Pause 不会被错误解释为 Recovery 故障，避免 Pause 后无法 resume 的死锁。

## 7. Recovery 不得自动清除人工阻断

### 实现

- 人工 Kill Switch、人工账户锁、Automation manual block 在恢复前后均保留。
- 对账过程不得清除人工账户锁。
- 存在人工阻断时，技术检查成功也不能进入 READY。
- `acknowledge_and_ready` 在人工阻断仍存在时拒绝 READY。
- 数据库检查点让该约束跨进程生效。

### 修改文件

## 独立安全审查后的额外修复

| 审查发现 | 修复与测试 |
| :--- | :--- |
| submit 后崩溃，在 Pause/Kill 下可能被 nack 至 DEAD | `_settle_committed_tasks` 先凭终态 Order 补 ack，再检查新开仓闸门；单测与真实多进程 Pause 场景均通过 |
| 账户 scope 未匹配时穿透到其他账户 | 显式 `continue`，并过滤账户锁；新增非目标账户不受影响的 scope 测试 |
| 陈旧 Checkpoint 可能长期伪装 READY | 90 秒 TTL；过期或存在 UNKNOWN Order 时动态降级 RECOVERY_MODE |
| 失效租约导致 ack→nack 二次异常 | 单独捕获 `InvalidLeaseError`，不再对失效租约 nack；新增回归测试 |
| 人工阻断数据库读取异常可能 Fail-Open | 全部改为带原因的 Fail-Closed；新增数据库异常测试 |

Pause 前积压任务仍以 TradePlan `expires_at` 为业务时效边界，Risk Rule 2 在提交前拒绝过期计划；本阶段未引入额外的任意秒数规则。
